# SQLAlchemy Development

## Workflow
1. Identify SQLAlchemy version and whether the project uses sync or async APIs.
2. Inspect engine/session lifecycle, dependency integration, model conventions, and migrations.
3. Define relationships, constraints, indexes, and loading strategy deliberately.
4. Keep session scope short and deterministic; close/rollback on failure.
5. Use transactions for atomic operations and avoid committing inside low-level helpers without an explicit contract.
6. Inspect generated SQL and query counts for performance-sensitive paths.
7. Test persistence behavior against the project's supported database.

## Rules
- Never share a Session across concurrent tasks or requests.
- Avoid lazy-loading surprises in serialization paths.
- Use selectinload/joinedload based on cardinality and query shape.
- Do not interpolate untrusted values into SQL strings; use bound parameters.
- Make cascade and delete-orphan behavior explicit.
- Use Alembic migrations for schema changes and review autogenerated migrations.
- Keep database constraints as a final integrity boundary, not just application validation.
